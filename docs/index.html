1. 概要

ADHT（Attention Deficit Hyperactivity Todo）は、ADHD 傾向のある人のためのシンプルな Todo アプリ。 タスクを登録すると AI が着手の入口を A・B・C の 3 案提案してくれるのが最大の特徴。 「何をやるかは分かっているが、どう手を付けていいか分からない」という着手障壁（タスク開始の実行機能の問題）を AI で下げる。

  • 利用者は安谷屋個人のみ。認証なし・課金なし。
  • まずは iPhone アプリとして提供。将来的に Android にも展開するため Flutter で開発する。

2. 機能要件

2.1 タスク登録

タスク登録時に入力する項目は以下の 4 つ。

項目 必須 内容
タイトル 必須 タスクの名前を自由入力。例:「HDMIキャプチャの調査を行う」
脳タイプ 必須 右脳（創造・直感系タスク）/ 左脳（論理・事務系タスク）の 2 択で振り分ける
Priority 必須 激重 / 重い / 普通 / 軽い の 4 段階から選択
期限 必須 日付を選択（DatePicker）

2.2 AI 着手提案

タスクを登録すると、AI が着手の入口を A・B・C の 3 案提案する。 例:「HDMIキャプチャの調査を行う」なら、「A. まず Amazon で『HDMI キャプチャ』と検索して売れ筋 3 つだけ見る」「B. YouTube でレビュー動画を 1 本だけ観る」…といった、最初の一歩が小さく具体的な行動を返す。

番号（1〜5）ではなく A・B・C のラベルにする理由: 数字で並べると「順にこなす STEP」に見えてしまい、着手障壁がかえって上がる。 提案は並列な選択肢であり「ピンときた入口をどれか 1 つ選ぶだけ」という見せ方にする。件数も 5 件だと選択自体が負荷になるため 3 件に絞る。

  • タイミング: タスク保存と同時に自動生成
  • 入力: タスクのタイトル・脳タイプ・Priority・期限（＋追加コンテキスト、下記）
  • 出力: 着手の入口 3 案（A・B・C ラベル、各 1〜2 文の短い日本語）。画面上のセクション名は「最初の一歩」
  • プロンプトでは「ADHD の人向けに、5 分以内に始められる具体的な最初の一歩を提案する」ことを指示する
  • オフライン時や API エラー時は提案なしでもタスク登録自体は完了できる（AI はあくまで補助）

タスク解像度アップ（AIとの自由チャット）

タスク詳細画面にAIとのチャット欄（ラベル:「AIと話して最初の一歩を決める」）を置き、自由入力で会話しながらタスクの解像度を上げる。 「予算は 1 万円以内」「もっと簡単にして」のように話しかけると、AI が返事をしつつA・B・C の入口を作り直す。

  • フォーム（textarea＋再生成ボタン）ではなくチャット形式にする — 「条件を入力する」より「相談する」方が着手障壁が低い
  • 会話履歴はタスクに保存し、以降の入口生成のコンテキストとして引き継ぐ
  • 会話は何度でも可能（1 回あたり 0.1 円未満なのでコスト上の制限は不要）

最初の一歩の「決定」フロー

提案を眺めるだけで終わらせず、タスクごとに「最初の一歩」を 1 つ決定するところまでをフローにする。決定の入口は 2 つ。

  1. A・B・C から選ぶ — 提案をタップするとそれが「決定した最初の一歩」になる
  2. AIと話して決める — チャットで相談すると、AI の返事に「👣 これを最初の一歩にする」ボタン付きの提案が添えられ、採用で決定できる
  • 決定後は A・B・C のリストを畳み、決定した一歩だけを強調表示する（情報量を絞る）。「選び直す」でいつでも解除可能
  • ブリーフィング画面には、決定済みならその一歩を「👣 決定した最初の一歩」として表示する

2.3 タスク管理（最小限）

  • タスク一覧表示（期限順・Priority 順の並び）
  • 完了チェック / 削除。完了したタスクは即座に消える（履歴は残さない）。リストが減っていくこと自体を達成感の演出にする
  • 右脳・左脳での絞り込み表示

2.4 タスクのインポート / エクスポート（JSON コピペ）

このアプリはバージョンがガンガン変わる前提。データ形式の変更や作り直しで既存タスクを失わないよう、 タスクを JSON でエクスポート / インポートできるようにする。まずは最シンプルにコピペで完結させる（ファイル連携・クラウド同期はやらない）。

  • エクスポート — 設定画面のボタンで全タスクを JSON 化してテキスト欄に表示＋クリップボードへ自動コピー。メモアプリ等に貼っておけばバックアップ完了
  • インポート — テキスト欄に JSON を貼り付けてボタンを押すと取り込み。全置き換え（確認ダイアログあり）。壊れた JSON・知らない形式はエラー表示して何も変更しない
  • 将来のバージョン間移行に備えて、JSON には形式バージョンを含むエンベロープを付ける: 
    {
  "format": "adht-tasks",
  "version": 1,
  "exportedAt": "2026-08-15T09:41:00Z",
  "tasks": [ { Task... } ]
}
    旧バージョンの JSON を読むときはインポート側でマイグレーションする（欠けたフィールドはデフォルト値で補完）

2.5 ブリーフィング画面（設計論点）

単なる「期限接近のプッシュ通知」ではなく、プレッシャーを感じさせずにタスク効率を最大化するブリーフィング画面を設ける。 設計の根拠となる ADHD の特性は以下の 4 点。

ADHD の特性 設計への含意
拒絶敏感性（RSD） 責める・恥をかかせる口調は「恥 → 回避 → タスク麻痺 → さらに遅れる」の悪循環を生む。個人アプリは開かれなくなったら終わりなので、アプリ自体が嫌悪刺激になる強め固定はリスクが大きい。
興味ベースの動機づけ 「重要だから」では動けず、緊急性・新規性・ゲーム性で動ける。締切の緊急性を「事実」として見せるのは有効（例:「期限まであと 2 日」）。人格への評価と切り離すのがポイント。
通知慣れ（habituation） 同じ文面の通知はすぐ視界から消える。AI で文面を毎回変えることが新規性の維持に直結する（このアプリの構成なら安く実現できる）。
着手障壁 「やれ」ではなく入口を渡す。ブリーフィングには必ず「最初の一歩」（§2.2 の提案から 1 件）と所要時間目安を添える。

ブリーフィング画面の設計案

  • 冒頭メッセージは「◯月◯日(◯) ADHTからのコメント」として人格化する — アプリからの通知ではなく相棒からの一言として受け取れる形にする
  • 「今日はこの 3 つだけ」方式 — 全タスクを見せず、期限 × Priority で選んだ最大 3 件だけ表示（圧倒の回避）
  • 各タスクに「最初の一歩 1 件 ＋ 所要時間目安 ＋ 期限の事実表示」を添える
  • 通知は 1 日 1 回の朝ブリーフィング ＋ 期限当日のみ。繰り返しのナグ通知はしない（通知慣れ・嫌悪の回避）
  • 完了操作でカードがその場で消える → 画面が軽くなっていく達成感

口調について（決定: ハイブリッド）

「基本やさしい × 常に具体的」を土台に、AI が日替わりで温度・キャラを揺らすハイブリッドで確定（2026-08-15）。

  • 強め固定（「あんたこれやってないやんけ」）は非推奨 — RSD により回避行動を誘発し、アプリを開かなくなる最悪ケースの確率が最も高い
  • やさしい固定（「サクッと終わりますよ」）も単体では弱い — 数週間で通知慣れして無風になる
  • ハイブリッド案: 通常はやさしく具体的、たまに軽いツッコミや煽らないユーモア（例:「これ 3 日目やで。5 分だけどう？」）を混ぜて新規性を保つ。人格否定・恥の演出は常に禁止をプロンプトで固定
  • 設定画面で口調プリセット（やさしめ / ツッコミ多め）を選べるようにし、実際に使いながら調整する

3. 画面構成

画面 内容
① タスク一覧 「すべて」表示では画面を縦に 2 分割し、左＝左脳タスク（青系背景）・右＝右脳タスク（オレンジ系背景）で色分け表示。右脳 / 左脳タブ選択時は 1 カラムのリスト。Priority と期限をバッジ表示。右下に「＋」ボタン。
② タスク作成 タイトル入力 → 右脳/左脳選択 → Priority 選択 → 期限選択 → 保存。保存と同時に AI 提案の生成を開始。
③ タスク詳細 タスク情報と「最初の一歩（AI提案）」A・B・C を表示。タップまたは AI とのチャットで最初の一歩を決定。決定後は決定カードのみを強調表示。完了・削除操作。
④ ブリーフィング 「今日はこの 3 つだけ」を表示（§2.5）。各タスクに最初の一歩・所要時間目安・期限を添える。朝の通知タップでこの画面に着地する。
⑤ 設定 口調プリセット（やさしめ / ツッコミ多め）、朝ブリーフィング時刻、タスクの JSON エクスポート / インポート（§2.4）。

4. データモデル

Task {
  id:          String   // UUID
  title:       String   // タスクタイトル
  brainType:   enum     // rightBrain | leftBrain（必須）
  priority:    enum     // gekiomo(激重) | omoi(重い) | futsuu(普通) | karui(軽い)（必須）
  deadline:    Date     // 期限（必須）
  chat:        [{role, text, proposal?}] // AI との会話履歴（§2.2）
  suggestions: [String] // AI の着手提案（3 件、A・B・C 表示）
  firstStep:   String?  // 決定した「最初の一歩」（§2.2、未決定は null）
  createdAt:   DateTime
}

Settings {
  toneBase:    enum     // gentle(やさしめ) | tsukkomi(ツッコミ多め)（§2.5）
  briefingHour: Int     // 朝ブリーフィング通知の時刻
}

完了フラグは持たない — 完了操作＝レコード削除（§2.3）。

保存先は端末内ローカル DB のみ（認証・サーバー同期なし）。 Flutter では drift（SQLite）または hive あたりの軽量ローカル DB を想定。

6. AI モデルの選定（コスパ比較）

用途は「短いタスクタイトルから日本語の提案 3 件を生成する」だけなので、1 リクエストあたり入力 500 / 出力 500 トークン程度の軽い処理。 どのモデルでも十分こなせるため、価格最優先で選定する（2026 年 8 月時点の調査）。

モデル 入力 $/1M 出力 $/1M 1 回あたり概算 備考
Gemini 2.5 Flash-Lite（推奨） $0.10 $0.40 約 0.06 円 無料枠あり（1 日 1,000 リクエスト程度）＝個人利用なら実質 0 円。ただし 2026-10-16 に廃止予定 → 後継 Gemini 3.1 Flash-Lite（$0.25/$1.50、約 0.2 円/回）へ移行
OpenAI GPT-5 nano $0.05 $0.40 約 0.05 円 従量課金では最安クラス。無料枠なし
OpenAI GPT-5 mini $0.125 $1.00 約 0.13 円 nano より品質高め
Claude Haiku 4.5 $1.00 $5.00 約 0.7 円 提案文の質・日本語の自然さは最良クラスだが単価は上

推奨: Gemini 2.5 Flash-Lite（Google AI Studio の無料枠）。 1 日数タスクの個人利用なら無料枠に収まり続けるためランニングコスト 0 円。 無料枠廃止や品質不満が出た場合の乗り換え先は GPT-5 nano（従量最安）。 仮に毎日 10 タスク登録しても、有料従量ですら月 20 円前後なので、実装を差し替えやすいよう AI クライアント部分は抽象化しておく。

1. 概要

ADHT（Attention Deficit Hyperactivity Todo）は、ADHD 傾向のある人のためのシンプルな Todo アプリ。 タスクを登録すると AI が着手の入口を A・B・C の 3 案提案してくれるのが最大の特徴。 「何をやるかは分かっているが、どう手を付けていいか分からない」という着手障壁（タスク開始の実行機能の問題）を AI で下げる。

  • 利用者は安谷屋個人のみ。認証なし・課金なし。
  • まずは iPhone アプリとして提供。将来的に Android にも展開するため Flutter で開発する。

2. 機能要件

2.1 タスク登録

タスク登録時に入力する項目は以下の 4 つ。

項目 必須 内容
タイトル 必須 タスクの名前を自由入力。例:「HDMIキャプチャの調査を行う」
脳タイプ 必須 右脳（創造・直感系タスク）/ 左脳（論理・事務系タスク）の 2 択で振り分ける
Priority 必須 激重 / 重い / 普通 / 軽い の 4 段階から選択
期限 必須 日付を選択（DatePicker）

2.2 AI 着手提案

タスクを登録すると、AI が着手の入口を A・B・C の 3 案提案する。 例:「HDMIキャプチャの調査を行う」なら、「A. まず Amazon で『HDMI キャプチャ』と検索して売れ筋 3 つだけ見る」「B. YouTube でレビュー動画を 1 本だけ観る」…といった、最初の一歩が小さく具体的な行動を返す。

番号（1〜5）ではなく A・B・C のラベルにする理由: 数字で並べると「順にこなす STEP」に見えてしまい、着手障壁がかえって上がる。 提案は並列な選択肢であり「ピンときた入口をどれか 1 つ選ぶだけ」という見せ方にする。件数も 5 件だと選択自体が負荷になるため 3 件に絞る。

  • タイミング: タスク保存と同時に自動生成
  • 入力: タスクのタイトル・脳タイプ・Priority・期限（＋追加コンテキスト、下記）
  • 出力: 着手の入口 3 案（A・B・C ラベル、各 1〜2 文の短い日本語）。画面上のセクション名は「最初の一歩」
  • プロンプトでは「ADHD の人向けに、5 分以内に始められる具体的な最初の一歩を提案する」ことを指示する
  • オフライン時や API エラー時は提案なしでもタスク登録自体は完了できる（AI はあくまで補助）

チャット＝ユーザー入力の支援（v1.3 で簡素化）

タスク詳細画面のチャット欄（ラベル:「AIと話して最初の一歩を決める」）は、 AI が凝った提案を考える場ではなく、ユーザー自身の言葉を「最初の一歩」に整えるのを支援する場とする。 v1.2 までの「会話のたびに A・B・C を作り直す」挙動は考えすぎだったため廃止。

  • ユーザーが「レシートを机に出すだけ」のように書くと、AI はその言葉を軽く整えた候補（例:「まず5分だけ『レシートを机に出すだけ』をやってみる」）と短い後押しを返す
  • 候補には「👣 これを最初の一歩にする」ボタンが付き、そのまま決定できる
  • チャットは A・B・C をいじらない — 提案の再生成はタスク編集（タイトル/脳タイプ変更）時のみ
  • 会話履歴はタスクに保存。回数制限なし（1 回あたり 0.1 円未満）

最初の一歩の「決定」フロー

提案を眺めるだけで終わらせず、タスクごとに「最初の一歩」を 1 つ決定するところまでをフローにする。決定の入口は 2 つ。

  1. A・B・C から選ぶ — 提案をタップするとそれが「決定した最初の一歩」になる
  2. AIと話して決める — 自分の言葉で書くと、AI がそれを整えた候補＋「👣 これを最初の一歩にする」ボタンを返し、採用で決定できる
  • 選択の即時フィードバック（v1.3） — A・B・C をタップしたらその場で選んだ行が「決定した一歩」に変化（✓マーク・ハイライト・他の案はフェードアウト）してから決定表示に切り替わる。画面遷移や戻る操作なしで、選んだことが必ず視覚的に分かること
  • 決定後は A・B・C のリストを畳み、決定した一歩だけを強調表示する（情報量を絞る）。「選び直す」でいつでも解除可能
  • ブリーフィング画面には、決定済みならその一歩を「👣 決定した最初の一歩」として表示する

タスク単位の AI 相談（v1.5 追加）

タスク詳細のチャット欄は、「最初の一歩」が決定済みかどうかでモードが切り替わる。 決定前は着手支援、決定後はそのタスクの伴走役になる。

状態 チャット欄
最初の一歩が未決定 「💬 AIと話して最初の一歩を決める」を表示（v1.3 の入力支援チャット）。決定するとこのチャットは非表示になる
最初の一歩が決定済み 「💬 AIにタスクを相談」を表示。進め方の相談（「次は何をすればいい？」）、詰まりの解消（「詰まった」→ 一歩をさらに小さく割る提案）、気分の吐き出し（励まし・進捗の肯定）に応じる。「終わった」と言えば進捗スライダーの更新や完了を促す
  • 「選び直す」を押して決定を解除すると、再び「AIと話して最初の一歩を決める」が表示される（モードは firstStep の有無に完全連動）
  • AI にはタスク情報（タイトル・脳タイプ・Priority・期限・進捗度・決定した最初の一歩・会話履歴）をコンテキストとして渡す
  • 会話履歴は 1 本のスレッドとしてタスクに保存（モードが切り替わっても履歴は続く）
  • タブの「AIに相談」（§2.6 = アプリ横断）とは別物。こちらはこのタスク専属の相談

2.3 タスク管理（最小限）

  • タスク一覧表示は軽い順（軽い → 激重。同じ重さなら期限が近い順）— 一番軽いものから始めるとエンジンがかかる、という着手優先の並び
  • タスク編集（v1.3 追加） — 詳細画面の「編集」から、タイトル・脳タイプ・Priority・期限を変更できる（作成シートを編集モードで再利用）。タイトルまたは脳タイプを変えた場合は A・B・C を再生成し、決定済みの最初の一歩もリセットする（内容が変わった提案を残さない）
  • 完了チェック / 削除。完了したタスクは即座に消える（履歴は残さない）。リストが減っていくこと自体を達成感の演出にする
  • 左脳・右脳での絞り込み表示

進捗度（v1.4 追加）

タスクに進捗度を 0% / 25% / 50% / 75% / 100% の 5 段階で記録できる。 記録はタスク詳細画面のスライダー（25% 刻みでスナップ）、表示は4 目盛りの充電池マーク。

  • 記録 UI＝スライダー（タスク詳細画面）。電池マークのタップ切替は「わかりにくい」ため不採用
  • 表示 UI＝充電池マーク（表示専用）。タスクカード・ブリーフィングカード・タスク詳細に表示。色は 25%＝赤 / 50%＝オレンジ / 75%以上＝緑、0% は空
  • 新規タスクの初期値は 0%
  • 進捗度は「完了」とは独立（完了＝削除の仕様は変わらない）。100% になっても自動では完了しない

UI ルール: 左脳は左、右脳は右

左脳と右脳が並ぶ場面では、必ず「左＝左脳、右＝右脳」の順に置く（一覧の縦 2 分割と同じ空間対応を全 UI で守る）。 一覧のフィルタは「すべて → 🧮左脳 → 🎨右脳」、タスク作成シートの脳タイプ選択も「左脳 → 右脳」の順。

2.4 タスクのインポート / エクスポート（JSON コピペ）

このアプリはバージョンがガンガン変わる前提。データ形式の変更や作り直しで既存タスクを失わないよう、 タスクを JSON でエクスポート / インポートできるようにする。まずは最シンプルにコピペで完結させる（ファイル連携・クラウド同期はやらない）。

  • エクスポート（v1.3: 2方式から選択） — ① コピー: 全タスクを JSON 化してクリップボードへ（メモアプリ等に貼ればバックアップ完了）／② ファイル保存: adht-tasks-YYYY-MM-DD.json として保存（アプリでは共有シート経由でファイル/AirDrop等へ）
  • インポート（v1.3: 2方式から選択） — ① 貼り付け: テキスト欄に JSON を貼って取り込み／② ファイル選択: JSON ファイルを選んで取り込み。いずれも全置き換え（確認ダイアログあり）。壊れた JSON・知らない形式はエラー表示して何も変更しない
  • 将来のバージョン間移行に備えて、JSON には形式バージョンを含むエンベロープを付ける: 
    {
  "format": "adht-tasks",
  "version": 2,
  "exportedAt": "2026-08-15T09:41:00Z",
  "tasks": [ { Task... } ]
}
    形式バージョンの履歴: version 1（〜アプリ v1.3.0）→ version 2（アプリ v1.4.0〜、progress（0〜100、25 刻み）追加）
  • 互換ルール（v1.4 で明文化）: 旧 → 新のインポートは常にサポートする（例: v1.3.0 でエクスポートした version 1 の JSON を v1.4.0 にインポート可。欠けたフィールドはデフォルト値で補完 — progress は 0%）。逆方向（新形式の JSON を旧アプリへ＝ダウングレードインポート）はサポートしない。自分より新しい version の JSON を読んだ場合は「アプリを更新してください」とエラー表示して何も変更しない

2.5 ブリーフィング画面（設計論点）

単なる「期限接近のプッシュ通知」ではなく、プレッシャーを感じさせずにタスク効率を最大化するブリーフィング画面を設ける。 設計の根拠となる ADHD の特性は以下の 4 点。

ADHD の特性 設計への含意
拒絶敏感性（RSD） 責める・恥をかかせる口調は「恥 → 回避 → タスク麻痺 → さらに遅れる」の悪循環を生む。個人アプリは開かれなくなったら終わりなので、アプリ自体が嫌悪刺激になる強め固定はリスクが大きい。
興味ベースの動機づけ 「重要だから」では動けず、緊急性・新規性・ゲーム性で動ける。締切の緊急性を「事実」として見せるのは有効（例:「期限まであと 2 日」）。人格への評価と切り離すのがポイント。
通知慣れ（habituation） 同じ文面の通知はすぐ視界から消える。AI で文面を毎回変えることが新規性の維持に直結する（このアプリの構成なら安く実現できる）。
着手障壁 「やれ」ではなく入口を渡す。ブリーフィングには必ず「最初の一歩」（§2.2 の提案から 1 件）と所要時間目安を添える。

ブリーフィング画面の設計案

  • 冒頭メッセージは「◯月◯日(◯) ADHTからのコメント」として人格化する — アプリからの通知ではなく相棒からの一言として受け取れる形にする
  • コメントの内容は「今日やらないといけないタスクのざっくりまとめ ＋ 応援」の2部構成（v1.3）。前半で今日の持ちタスク（期限当日のものは名指し）を要約し、後半で「まず5分だけ」「1つ動いたら今日は勝ち」のようなハードルを下げる応援で締める
  • 更新ボタン（v1.3） — コメント右上の「↻」でブリーフィングをいつでも作り直せる（タスク状況の変化を反映＋文面ガチャによる新規性）
  • 「今日はこの 3 つだけ」方式 — 全タスクを見せず、期限 × Priority で選んだ最大 3 件だけ表示（圧倒の回避）。表示順は軽い順（選定は緊急度、並びは着手しやすさ）
  • 各タスクに「最初の一歩 1 件 ＋ 所要時間目安 ＋ 期限の事実表示」を添える
  • 通知は 1 日 1 回の朝ブリーフィング ＋ 期限当日のみ。繰り返しのナグ通知はしない（通知慣れ・嫌悪の回避）
  • 完了操作でカードがその場で消える → 画面が軽くなっていく達成感

口調について（決定: ハイブリッド）

「基本やさしい × 常に具体的」を土台に、AI が日替わりで温度・キャラを揺らすハイブリッドで確定（2026-08-15）。

  • 強め固定（「あんたこれやってないやんけ」）は非推奨 — RSD により回避行動を誘発し、アプリを開かなくなる最悪ケースの確率が最も高い
  • やさしい固定（「サクッと終わりますよ」）も単体では弱い — 数週間で通知慣れして無風になる
  • ハイブリッド案: 通常はやさしく具体的、たまに軽いツッコミや煽らないユーモア（例:「これ 3 日目やで。5 分だけどう？」）を混ぜて新規性を保つ。人格否定・恥の演出は常に禁止をプロンプトで固定
  • 設定画面で口調プリセット（やさしめ / ツッコミ多め）を選べるようにし、実際に使いながら調整する

2.6 AIに相談（v1.3 追加）

タスク単位のチャット（§2.2）とは別に、アプリ全体を横断して AI に相談できるタブを設ける。 タブ構成は「今日 / タスク / 相談 / 設定」の 4 つになる。

  • タスクの照会 — 「今日明日でやらないといけないタスクはなに？」と聞くと、期限が近いタスクを軽い順で答え、最初の一歩を添える
  • 気分の相談 — 「だるくてやる気がしない」のような気持ちの吐き出しにも応じる。責めない・説教しないを固定し、「全部やらなくていい」と受け止めた上で、一番軽いタスクの入口を 1 つだけ差し出す（やらない選択も肯定する）
  • AI には全タスク（タイトル・Priority・期限・決定済みの最初の一歩）と口調設定をコンテキストとして渡す
  • 会話履歴は端末に保存。回数制限なし

3. 画面構成

画面 内容
① タスク一覧 「すべて」表示では画面を縦に 2 分割し、左＝左脳タスク（青系背景）・右＝右脳タスク（オレンジ系背景）で色分け表示。フィルタの並びは「すべて → 左脳 → 右脳」（§2.3 の UI ルール）。左脳 / 右脳タブ選択時は 1 カラムのリスト。Priority と期限をバッジ表示。右下に「＋」ボタン。
② タスク作成 タイトル入力 → 右脳/左脳選択 → Priority 選択 → 期限選択 → 保存。保存と同時に AI 提案の生成を開始。
③ タスク詳細 タスク情報と「最初の一歩（AI提案）」A・B・C を表示。タップまたは AI とのチャットで最初の一歩を決定。決定後は決定カードのみを強調表示。完了・削除操作。
④ ブリーフィング 「今日はこの 3 つだけ」を表示（§2.5）。各タスクに最初の一歩・所要時間目安・期限を添える。カードのタップでタスク詳細へ遷移（完了・提案ボタンは除く）。朝の通知タップでこの画面に着地する。
⑤ AIに相談 アプリ横断の AI 相談チャット（§2.6）。タスクの照会（今日明日の期限など）と気分の相談に応じる。タブバーの3番目。
⑥ 設定 ブリーフィングの口調（やさしめ / ツッコミ多め）、朝ブリーフィング時刻、タスクの JSON エクスポート / インポート（§2.4）、バージョン表示「ADHT vX.Y.Z」。

4. データモデル

Task {
  id:          String   // UUID
  title:       String   // タスクタイトル
  brainType:   enum     // rightBrain | leftBrain（必須）
  priority:    enum     // gekiomo(激重) | omoi(重い) | futsuu(普通) | karui(軽い)（必須）
  deadline:    Date     // 期限（必須）
  chat:        [{role, text, proposal?}] // AI との会話履歴（§2.2）
  suggestions: [String] // AI の着手提案（3 件、A・B・C 表示）
  firstStep:   String?  // 決定した「最初の一歩」（§2.2、未決定は null）
  createdAt:   DateTime
}

Settings {
  toneBase:    enum     // gentle(やさしめ) | tsukkomi(ツッコミ多め)（§2.5）
  briefingHour: Int     // 朝ブリーフィング通知の時刻
}

完了フラグは持たない — 完了操作＝レコード削除（§2.3）。

保存先は端末内ローカル DB のみ（認証・サーバー同期なし）。 Flutter では drift（SQLite）または hive あたりの軽量ローカル DB を想定。

6. AI モデルの選定（コスパ比較）

用途は「短いタスクタイトルから日本語の提案 3 件を生成する」だけなので、1 リクエストあたり入力 500 / 出力 500 トークン程度の軽い処理。 どのモデルでも十分こなせるため、価格最優先で選定する（2026 年 8 月時点の調査）。

モデル 入力 $/1M 出力 $/1M 1 回あたり概算 備考
Gemini 2.5 Flash-Lite（推奨） $0.10 $0.40 約 0.06 円 無料枠あり（1 日 1,000 リクエスト程度）＝個人利用なら実質 0 円。ただし 2026-10-16 に廃止予定 → 後継 Gemini 3.1 Flash-Lite（$0.25/$1.50、約 0.2 円/回）へ移行
OpenAI GPT-5 nano $0.05 $0.40 約 0.05 円 従量課金では最安クラス。無料枠なし
